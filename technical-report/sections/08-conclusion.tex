\section{Conclusion}\label{sec:conclusion}
\acresetall

In this paper, we looked into tool support that keeps the data of a \SLR traceable.
We presented \SaiLoR, an open-source desktop tool for screening, data extraction, and consolidation.
A \SaiLoR project consisted of plain \JSON files that a schema described and that git versioned.
Reviewers worked independently in their own seats and linked their answers to evidence in the papers.
A consolidator resolved disagreements with the help of agreement statistics, and \SaiLoR merged concurrent changes field by field.
Optional \LLM assistance proposed answers with evidence, but a human reviewed every proposal before \SaiLoR applied it.

We also explained the main architecture decisions.
These were the local files instead of a server, git as collaboration layer, the security model, the move from Electron to Tauri in version 2.0.0, and the support for large projects.
To keep the tool itself traceable, we documented 510 requirements.
Of these requirements, 95\% linked to implementing source code and 94\% linked to at least one automated test.
The test suites held 3709 unit tests, 56 integration tests, and 135 Rust tests.
Mutation testing of the model code added about 350 unit tests and found no bug in the production code.
We made the source code of \SaiLoR available on GitHub under the GPL-3.0 license, with a Zenodo concept \DOI for all versions.
An online demo let readers try \SaiLoR in the browser without an installation.

Overall, we argued that plain files and git can keep review data traceable, but the benefit for reviewers remains open.

Regarding the tool, we want to retest the user interface, including the guard against reload shortcuts, in the web views of all three operating systems.
We also want to extend the mutation testing to the store, the user interface components, and the Rust backend.
In addition, we want to verify the local model runtime on \GPUs with CUDA and Vulkan and enable the managed installation once llama.cpp provides the required route.

In future research, we want to evaluate \SaiLoR in a user study with reviewers who conduct a real \SLR.
We want to find out whether the tool reduces the effort of extraction and consolidation and whether the recorded history helps others to trace the review.
We also want to measure how accurate the \LLM proposals are and how they influence the decisions of reviewers.

Lastly, we want to have the requirements reviewed by people other than the developer and check the traceability matrix automatically in the \CI.
